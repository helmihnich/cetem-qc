- (note) Evidence 2026-10-03: no reset path exists. regenerateOwnTeamEmployeeCredential only updates pre-activation (must_change_password=true) active own-team employees and does not revoke sessions; web shows Regenerer for every active employee, so activated employees get 404.
- (note) Evidence: revokeAccountSessions exists unused; requireSession denies everything but session/password routes while must_change_password; replacePasswordAfterAuthentication requires must_change_password=true and verifies the temporary credential.
- (note) Evidence: no security-event logging or audit table exists in apps/api; AD-11 requires structured logs with event kind and no credentials; UX OD-09 forbids secrets in logs/audit.
- (note) Evidence: employee list contract exposes active but not activation state; mobile treats 401 on online check as reauthenticate-online and keeps local data (OD-01).
- (decision) PO decision (pipeline rules) supersedes UX EXPERIENCE.md line 'do not extend into an unspecified post-activation password-reset workflow': reset by Responsable for Employe, operator CLI for Responsable, no email.
- (capability) CAP-1 Responsable resets an Employe password: own-team active Employe, any activation state; new one-time temporary credential, must_change_password=true, all sessions revoked, one transaction.
- (capability) CAP-2 One-time hand-over on web: reuse Story 3.2 W1a dialog (copy, acknowledgement, no redisplay) with reset title; button Reinitialiser le mot de passe for active employees.
- (capability) CAP-3 Operator CLI resets a Responsable password: pnpm --filter @cetem-qc/api reset:responsable-password prompts for email, prints credential once, forces change, revokes sessions; documented.
- (capability) CAP-4 Forgotten-password hints on login screens: web 'Mot de passe oublie ? Contactez votre administrateur.' mobile 'Mot de passe oublie ? Contactez votre Responsable.'
- (capability) CAP-5 Reset audit: persisted attributed audit row plus one structured log line per reset; never credential, hash or email.
- (capability) CAP-6 Server-side authorization and denials: role responsable only, own team only (cross-team = 404 like unknown), deactivated own-team Employe = 409 EMPLOYEE_INACTIVE, no mutation on denial.
- (decision) New endpoint POST /api/v1/employees/{employeeId}/password-reset (operationId resetEmployeePassword) returning EmployeeCredentialResponse; existing /credential regenerate endpoint and its tests stay unchanged.
- (decision) Web replaces the Regenerer button by Reinitialiser le mot de passe for active employees (reset is a superset: works pre- and post-activation, invalidates previous credential); avoids exposing activation state in the list contract.
- (decision) Deactivated own-team Employe: 409 EMPLOYEE_INACTIVE (Responsable already sees the employee in roster, so no disclosure); other team, Responsable target, unknown id or malformed id: 404 EMPLOYEE_NOT_FOUND.
- (decision) Audit table identity_password_resets (migration 0008): account_id, reset_by_account_id (null for operator), channel responsable|operator, created_at; CHECK channel=responsable iff actor set.
- (decision) Log line: console.info JSON {event: identity.password_reset, channel, accountId, resetByAccountId}; emitted after commit; ids only.
- (decision) Mobile offline effect follows OD-01: revocation acts like server-token loss; the device keeps offline access within its 7-day window until its next online check, which returns 401 and requires sign-in with the temporary credential; local drafts preserved, never deleted.
- (decision) CLI acts only on an active account with role responsable; unknown, inactive or employe email fails with one generic message that never echoes input or credential; email via prompt, not argv.
- (decision) Web UI is tested by static rendering with react-dom/server (no new render infrastructure); route proxy tested like the credential route.
- (constraint) Credential never logged, never stored in recoverable form, returned once with Cache-Control no-store; reset is one transaction (hash+flag, session revoke, audit row) that leaves the old password and sessions working on failure.
- (constraint) Server-side role and team checks only; team derived from the session, never the request; endpoint is behind requireSession default-deny (blocked during must_change_password).
- (constraint) No email/SMS; UI French via packages/i18n; no change to Story 2.3 activation flow, session duration or OD-01 offline window.

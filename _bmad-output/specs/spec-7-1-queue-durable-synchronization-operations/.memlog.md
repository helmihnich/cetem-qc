- (direction) Automated pipeline (headless, express distill) requests Story 7.1 spec from .automation/task.md; no code; story exists in epics.md (no new entry); set ready-for-dev and epic-7 in-progress.
- (note) Evidence 2026-10-04: mobile local store is SQLCipher SQLite v2 (local_drafts, synchronized_tasks) behind DraftDatabase/DraftRepository; no outbox, snapshot or sync code exists; API has no draft-sync or submission endpoint; App autosaves through drafts.save; signOut never deletes drafts.
- (capability) CAP-1 Atomic draft-sync operation: every local draft save commits the draft row, an immutable snapshot and a sync-draft outbox operation (operation ID, idempotency key, base revision) in one SQLite transaction.
- (capability) CAP-2 Atomic submission request: a repository requestSubmission saves the current values and commits an immutable submission snapshot plus a submit outbox operation in one transaction; while it is unresolved the draft cannot be saved or deleted.
- (capability) CAP-3 Outbox lifecycle: an item stays until a definitive server outcome is recorded locally in the same transaction that resolves it; resolved items and their snapshots are kept.
- (capability) CAP-4 Bounded retry sync engine: processes the authenticated employee's items per task in FIFO order through an injected transport port, same idempotency key on every attempt, bounded attempts with backoff, then pauses until a new trigger; correctness never depends on background execution.
- (capability) CAP-5 Preservation across restart, logout, expiry, upgrade and transient failure: no path deletes an unresolved item or its snapshot; schema upgrade v2->v3 is additive.
- (decision) Scope: 7.1 is mobile-only (store, repository, engine with transport port). No API, OpenAPI or packages/schemas change. Real HTTP transport and App triggers are wired by the story that provides the server command (7.3) or renders sync state (7.2).
- (decision) Soumettre button, pending read-only rendering and French sync states belong to Story 7.2 (its AC owns pending read-only and distinct states); 7.1 exposes requestSubmission and status reads only, proven by tests.
- (decision) Base revision = last server revision of the task's audit known to this device (0 when never acknowledged), stored per employee+task in task_sync_state. When an operation is accepted, later unresolved operations of the same task that carry the same base are advanced to the returned revision in the same transaction (own change, not a conflict).
- (decision) Supersession: on save, an unresolved sync-draft operation of the same task with attempt_count 0 is replaced (row and snapshot removed, new op inserted) in the same transaction, because it was never sent and the new snapshot is a superset. Attempted operations are never replaced. Submit operations are never superseded.
- (decision) requestSubmission supersedes never-attempted sync-draft ops of the task (submission carries the full payload); attempted sync-draft ops stay ahead of it in FIFO order.
- (decision) Explicit delete (FR-019) and deleteUnreadable are refused while an unresolved submit op exists for the task; otherwise they remove the task's unresolved sync-draft ops and their snapshots in the same transaction (explicit confirmed discard, not silent).
- (decision) Definitive outcomes: accepted (with server revision), rejected (validation), conflict (with server metadata). Retryable: network error, timeout, no response, HTTP 408/429/5xx. Blocking (not definitive, item kept, run stops): 401/403 incl. ACCOUNT_DEACTIVATED and TASK_NOT_ASSIGNED. Any other response is treated as blocking, never as definitive.
- (decision) Retry bound: at most 5 attempts per item per run, backoff 1 s, 2 s, 4 s, 8 s between attempts; then status retry-paused with last error. A new trigger (start, reconnect, foreground, save, explicit retry) starts a new run. attempt_count is cumulative and never resets item identity. Technical parameters, not CETEM business rules.
- (decision) Operation ID and idempotency key are two distinct random UUIDs (expo-crypto randomUUID via the injected createId), persisted at creation and never regenerated.
- (decision) No client-side submission validation is invented; DEP-01/02 blocking validations are enforced by the server in 7.3. Submission is refused locally only for legacy-content drafts (not paper-form structured) and drafts that fail parseLocalDraft.
- (decision) Snapshot content = the LocalDraft envelope JSON as saved (values + catalogue/schema/rule identity), no calculated results; server recalculates (retro action item 15). Snapshots are insert-only.
- (constraint) One SQLite exclusive transaction per write; no UPDATE of snapshot rows; all rows scoped by employee_id; engine sends only the authenticated employee's items and only with active offline authorization and connectivity.
- (constraint) No change to catalogue, rule identity, domain calculations, OpenAPI or API. UI unchanged in 7.1. Encryption key and SQLCipher DB unchanged.
- (assumption) Server draft-sync command has no owning story in epics.md; recorded as a hand-off for the 7.3 author (add to 7.3 or a new story). Does not block 7.1 because the transport is a port.

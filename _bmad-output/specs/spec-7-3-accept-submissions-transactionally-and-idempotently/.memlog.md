- (capability) CAP-3 Idempotent replay: same idempotency key from same actor with same request returns the stored outcome (status and body) with no new row; mismatched reuse is refused without disclosure.
- (capability) CAP-4 Stale base revision returns conflict with current-version metadata and changes nothing else.

- (decision) Server draft-sync command placed in 7.3 (resolves 7.1 deferred-work): FR-021 requires drafts to synchronize; with a real transport, attempted sync-draft items precede the submit item of the same task in engine order, so a missing endpoint would block every submission. Same idempotency store and revision check. Scope decision, not a CETEM rule.
- (decision) Revision model: one audit per task, created lazily; current_revision 0 when absent; every accepted operation (draft-sync or submission) adds revision current+1; base must equal current, else conflict.
- (decision) Endpoints POST /api/v1/employee/tasks/{taskId}/draft-syncs and /submissions; 200 accepted, 409 conflict, 422 rejected (outcome bodies, stored); 400 envelope error, 401, 403, 404 TASK_NOT_FOUND, 422 IDEMPOTENCY_KEY_REUSED not stored.
- (decision) Check order: session, role employe, task assignment (404, no disclosure), envelope, then in transaction: lock audit, idempotency lookup, already-submitted rejection, base check, payload validation, accept.
- (decision) Every definitive outcome (accepted, rejected, conflict) is stored with the idempotency key in the same transaction; replay returns stored status and body byte-equal.
- (decision) Assignment is checked on replay too (SEC-003); a reassigned task returns 404 and the item stays blocked for 8.4.
- (decision) After an accepted submission, a new operation for that audit is rejected AUDIT_ALREADY_SUBMITTED (stored). Broader mutation refusal is 7.4.
- (decision) Accepted date is server now(); client savedAt and local draft revision are recorded for traceability only.

- (decision) Sync routes accept JSON bodies up to 256 kB; other routes keep 32 kB. NUL in any payload string is INVALID_PAYLOAD (PostgreSQL jsonb cannot store it). Technical limits, not CETEM rules.

- (direction) Headless pipeline run (.automation/task.md): create the 7.4 spec, approve it, set sprint-status ready-for-dev. Express mode.
- (note) Code baseline 5b38b1e: 0009 makes audit_revisions, audit_submissions, sync_operation_outcomes insert-only; the audits row stays updatable; processSyncOperation rejects any operation on a submitted audit with a stored 422 AUDIT_ALREADY_SUBMITTED; a Responsable gets 403 on the sync routes; no other API route touches audits; no read query for accepted evidence exists.
- (capability) CAP-1 Database freeze: once an audit is submitted, its audits row cannot be updated or deleted by any SQL path; revisions and submission stay insert-only; the linked task cannot be deleted.
- (capability) CAP-2 API refusal for both roles: every mutation attempt by the Employe or a Responsable on an accepted audit is refused and leaves the accepted evidence byte-equal.
- (capability) CAP-3 Accepted snapshot available to authorized review: a public audits query returns payload, results, identity, submitting actor/date and task link, scoped to the Responsable's own team, with no disclosure otherwise.
- (capability) CAP-4 No in-place correction or replacement: one audit per task and one submission per audit are pinned by tests, so a later correction or replacement must be a new task/audit record.
- (decision) Freeze trigger on audits (migration 0010): BEFORE UPDATE refuses when OLD.state = submitted; BEFORE DELETE always refuses. Reason: audits is the only updatable evidence table after 7.3.
- (decision) Task row of a submitted audit: DELETE is already refused by the audits.task_id FK (RESTRICT), pinned by a test; UPDATE of task metadata is not frozen, because it is not measurements/comments and Story 9.1 may change the task state projection.
- (decision) Assignments are not frozen in 7.4: reassignment and deactivation recovery belong to 8.4 (AD-5); submitted_by is stored independently of the assignment.
- (decision) No new HTTP endpoint and no OpenAPI change: the Responsable read endpoint, web view and access log stay in 9.1 (7.3 non-goal, 9.1 AC). 7.4 delivers the public audits query 9.1 will call.
- (decision) Review authorization: tasks exposes getOwnTeamTaskId(pool, responsableId, taskId) publicly; audits query getAcceptedSubmissionForReview composes it and returns undefined for another team, an unknown task or no accepted submission.
- (decision) No lineage table in 7.4: AD-4 creates replacement-control links in CreateReplacementControl (8.3); rejected-submission-correction applies to a non-accepted audit (8.2); a sync-conflict-revision never reaches a submitted audit because the submitted check precedes the revision check.
- (decision) Mutating-route inventory test: compares the non-GET /api/v1 routes registered by createApp with a fixed list, so a new mutating route fails until its freeze behaviour is tested.
- (decision) A replay of an already-stored outcome (including the original accepted submission) returns the stored body and is not a mutation; tested as writing nothing.
- (constraint) No OpenAPI, schema, api-client, mobile or i18n change; AUDIT_ALREADY_SUBMITTED wording stays as in 7.3; boundaries:check holds (audits owns the migration and review query, tasks owns the team query).
- (decision) TRUNCATE is refused on audits, audit_revisions, audit_submissions and sync_operation_outcomes by statement-level triggers, closing the gap row triggers leave; the test harness drops per-test schemas and never truncates.
- (note) Comments are catalogue area fields inside payload.values (voltage.accuracy.comments ... comments.general), so freezing the revision payload freezes comments; no separate comment table exists.

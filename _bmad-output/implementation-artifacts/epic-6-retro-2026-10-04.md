## Findings

### Spec-to-implementation reconciliation

F1. **Story 6.1/6.2 acceptance criteria in `epics.md` still describe the retired workbook rule set.** Story 6.1 says « preserves the explicit 0.49 linearity factor and formula wrapper ». Story 6.6 removed that factor, the 3-row reproducibility and the initial linearity under PO direction (`epics.md` Story 6.6 AC; `packages/domain/src/graphie-calculations.ts` now exports only the five paper tests). `epic-6-context.md` acknowledges the conflict (« Where they conflict, the Story 6.6 direction is the current one »), but `epics.md` itself has no supersession note on 6.1/6.2. **Disposition:** fix now (spec reconciliation, proposed). **Prevention:** when a story supersedes earlier ACs, annotate the superseded ACs in the same story.

F2. **The Story 6.4 review view is not reachable by a Responsable in the running web app.** `apps/web/src/app/graphie-calculation-review.tsx` is imported only by its render test. `page.tsx` does not render it. The 6.4 delivery notes hand the wiring to Story 9.1 on purpose (« Hand-off to Story 9.1 »), because accepted snapshots arrive only with Epic 7. The AC « readable in the web review surface » is therefore met at component level (render tests W1–W9), not end to end. **Disposition:** accept as-is (planned hand-off). Tracked by Story 9.1.

F3. **The server cannot yet recalculate a whole draft through the API module.** `apps/api/src/modules/calculations/calculations.ts` wraps only the single per-test `graphieCalculations` functions and has no production caller. Story 6.4 moved the whole-form path (`calculateGraphieResults`, string parsing via `parseGraphieReading`) into `packages/domain/src/graphie-inputs.ts`, and mobile uses that path. Epic 7 acceptance must recalculate through the same path to keep the 6.2 parity promise. **Disposition:** defer to Stories 7.3/7.4 (action item). The deferred 6.4 identity/results consistency check belongs to the same work.

### Architecture delta

F4. **`@cetem-qc/i18n` now contains presentation logic and depends on `@cetem-qc/domain`.** In `8ca0508`, `packages/i18n/src/graphie-results.ts` (148 lines) and `packages/i18n/package.json` gained a `./graphie-results` export and a domain dependency. That package was previously strings only. The 6.4 spec approved this so mobile and web share one presenter (`shared-presentation.md`), and `boundaries:check` passes. **Disposition:** accept. If more presenters appear, record in the architecture spine that i18n hosts shared French presenters.

F5. **Tolerance comparison uses an epsilon of 1e-9.** `TOLERANCE_EPSILON` is defined in `graphie-calculations.ts:120`. This is not an invented business rule: it was asked and answered as Q1 during 6.6 spec approval (`specs/spec-6-6-…/.memlog.md:43`, `tolerances.md`). It absorbs floating-point noise only, and boundary tests B11–B15 cover it. **Disposition:** accept. Recorded so later retros do not flag it again.

### Cross-story boundaries

F6. **Story order changed: 6.6 and 6.7 landed before 6.3/6.4/6.5.** Story 6.6 was added mid-epic and blocked 6.3 (`sprint-status.yaml` comment « must land before 6-3 »). Story 6.7 then closed the gate gaps found in 6.6 review (`deferred-work.md`, five entries « resolved: Story 6.7 »). The pipeline's precondition check (`run-pipeline.ps1`, « Story 6.6 is not done ») enforced the order. **Disposition:** accept. **Lesson (positive):** adding a rule-change story and a harness story before the UI stories meant the UI stories were built and verified against the final rule set and full gates.

F7. **Gates went from partial to complete during the epic.** Before 6.7, `apps/api` `test` ran only the calculations suite, and `packages/*` had no typecheck (`deferred-work.md` 6.6 entries). After `64c1e3f`, every package discovers its tests by pattern, and PostgreSQL suites run against an isolated local schema with 0 skipped. Verified in this retro: api 92/92, mobile 151/151, domain 50/50, web 31/31, i18n 7/7, 0 skipped. **Disposition:** accept (win). Remaining gaps: F9.

### Process and provenance

F8. **Commit attribution is unreliable for 6.1 and 6.2, and operator edits are mixed into story commits.** `6b8126c` does not name Story 6.1. `e711d39` holds the full Story 6.2 change (`apps/api/src/modules/calculations/*`, `apps/mobile/graphie-calculation-service.*`, `local-drafts/model.ts`) under the subject « add password replacement proxy and session management tests ». The `Assert-Gates` logic was not changed. **Disposition:** fix now (process). **Prevention:** a commit subject must name its story, and pipeline or tooling edits go in their own commit.

F9. **Some gate-coverage gaps are still open (deferred, owned).**
- Mobile test files are excluded from `apps/mobile` typecheck (`deferred-work.md`, Story 6.7).

**Disposition:** defer. A decision on the gates is needed (action item).

F10. **The approved-acceptance runner is permissive while the dataset is empty.** Three deferred entries from the 6.5 review: partial `expected.values` is allowed, value keys are not checked against field IDs, and case ids must be unique across the whole dataset. None of these can happen today, because `graphie-calculations.approved-acceptance.ts` ships an empty dataset and `graphieAcceptanceStatus` reports blocked (DEP-02). **Disposition:** defer until the CETEM dataset arrives (action item).

F11. **Input grammar accepts ASCII digits only.** `parseGraphieReading` uses `\d` without the `u` flag (`deferred-work.md`, 6.3 review). Not verified on devices. **Disposition:** defer. Open question.

## Findings

### Spec-to-implementation reconciliation

F1. **Scope moved into Story 7.3: the server draft-sync command, the HTTP transport and the automatic sync triggers.** The 7.3 AC in `epics.md` covers submissions only. Story 7.1 found that no story owned the `sync-draft` endpoint (`deferred-work.md`, « Deferred from: Story 7.1 spec »). The 7.3 spec placed it in 7.3 with a recorded reason: with a real transport, a missing endpoint would block every submission, because draft-sync items come first in engine order (`specs/spec-7-3-…/.memlog.md:17`). `epics.md` 7.3 traceability was updated in `5b38b1e` to say so. **Disposition:** accept (recorded scope decision, not a CETEM rule). **Prevention:** none needed; the hand-off chain worked as designed.

F2. **The accepted snapshot is readable only through a query with no production caller, and task lists still say `draft`.** `getAcceptedSubmissionForReview` (`apps/api/src/modules/audits/queries/accepted-submission.ts:46`) is used only by `freeze-routes.postgres.test.ts` (Q1–Q2). The Responsable route, access log and web view are handed to Story 9.1 (`specs/spec-7-4-…/delivery-notes.md`, « Story 9.1 »). The OpenAPI task `state` is still the constant `draft` after acceptance (`deferred-work.md`, « Deferred from: Story 7.3 spec »). So the 7.4 AC « remain available to authorized review » is met at query level, not end to end. This is the same shape as Epic 6 F2. **Disposition:** accept as-is (planned hand-off, tracked by 9.1).

### Duplication map

F3. **Two structural validators for the same Graphie payload.** The device parser `parseGraphiePayload` (`apps/mobile/graphie-pov-catalogue.ts:30-58`) and the server validator `validateGraphiePayload` (`packages/domain/src/graphie-catalogue.ts:237-286`) implement the same key, identity, field-ID and choice-option rules separately. The domain docstring says so: « the same rules as the device's saved-payload parser, plus NUL characters … and legacy content on a submission » (`graphie-catalogue.ts:231-235`). The rules already differ: a value with a NUL character (or, per the deferred 7.3 entry, an unpaired surrogate) is saved on the device and later refused by the server as a definitive `INVALID_PAYLOAD` rejection. No keyboard is expected to produce these characters, so it is not reachable in practice today. When DEP-01/02 validations arrive, both copies would have to change together. **Disposition:** defer (action item). **Prevention:** when a story moves a rule set into `packages/domain`, the old copy should delegate to it in the same story.

### God-class / size growth

F4. **`apps/mobile/App.tsx` is now 1,511 lines (+225 net in this epic), and `App.render.test.tsx` is 3,004 lines (+717).** `git_evidence.py`: `App.tsx` changed in 7.2 and 7.3; the render test changed in 7.1, 7.2 and 7.3. Story 7.2 added outbox state, Soumettre with confirmation, the lock, retry and labels. Story 7.3 added engine creation, transport wiring and the automatic triggers (`App.tsx:114-126`). The sync logic itself is already in small modules (`sync/sync-engine.ts` 175 lines, `sync/task-sync-state.ts`, `sync/acceptance-line.ts`). What stays in `App.tsx` is the wiring and React state. Stories 8.1 and 8.2 are told to extend this same area (`specs/spec-7-2-…/delivery-notes.md`, « Story 8.1 / 8.2 »). **Disposition:** defer (action item): extract the sync wiring into its own hook or module before Epic 8 adds the conflict and correction UI.

### Pattern divergence

F5. **A mutable test-seam object is exported from a production command module.** `auditCommandTestSeams` (`apps/api/src/modules/audits/commands/audit-revisions.ts:36-40`) lets tests inject a failure after the revision insert and replace the calculation. It is used at `audit-revisions.ts:80,96,106` and reset by `test-support/sync-fixture.ts:71-72`. Elsewhere in this epic, dependencies are injected (`createSyncEngine` options, `createAppSyncTransport(api, timers)`). The comment says « Never set in production », and nothing in production sets it. **Disposition:** accept. It is what makes A14 (identity invariant) and the rollback test possible without a DI layer in the API. Recorded so later retros do not flag it again.

### Architecture delta

F6. **New API modules `audits` and `sync`, and two migrations.** `sync/commands/process-sync-operation.ts` imports `audits/commands/audit-revisions.js`. `audits/queries/accepted-submission.ts` imports `tasks/queries/own-team-task.js`. Both go through the `commands`/`queries` entry points that `boundaries:check` allows, and the check passes. The catalogue moved from `apps/mobile` into `packages/domain/src/graphie-catalogue.ts` (+286; mobile −183) so the server validates against the same fields. **Disposition:** accept.

F7. **The database freeze holds only against a role that cannot alter the tables.** Migration 0009 makes revisions, submissions and outcomes insert-only. Migration 0010 freezes submitted `audits` rows and refuses TRUNCATE on the four evidence tables. But migrations and the API share `DATABASE_URL`, so the runtime role owns the tables and could disable the triggers (`deferred-work.md`, « Deferred from: code review of spec-7-4 »). **Disposition:** defer to Epic 12 deployment templates (action item).

## Action items

1. **Single structural payload validator:** make the device's `parseGraphiePayload` (`apps/mobile/graphie-pov-catalogue.ts`) delegate its shared rules to the domain `validateGraphiePayload`. Keep only the device-specific parts locally: Story 5.3 legacy content and the compatibility error. The device and the server would then accept and refuse the same payloads, including NUL and, once specified, lone surrogates. Owner: mobile and domain maintainers (Story 8.2 or the next validation change). Source: F3.
2. **Extract the mobile sync wiring from `App.tsx` before Epic 8:** move engine creation, triggers, outbox refresh and run state into a hook or module, with its own tests, before 8.1/8.2 add conflict and correction UI. Owner: mobile maintainers / Story 8.1 author. Source: F4.
3. **Separate database roles in the deployment templates:** split a migration/owner role from a runtime role that has no TRIGGER, TRUNCATE or DDL rights, so the 0009/0010 freeze cannot be disabled by the API's own connection. Document it in the French deployment guide. Owner: Epic 12 story author (12.1). Source: F7, `deferred-work.md` 7.4 entry.
4. **End-to-end sync demonstration:** Story 12.4 must run the real mobile engine and HTTP adapter against a live API on PostgreSQL: save offline, reconnect, accept, replay and freeze. Today these are proven by separate test sets only. Owner: Story 12.4 author. Source: Behavior verification.

All four are proposals for the normal dev/PO loop. No code or spec was changed by this retrospective.

## Acceptance verdict

**Accepted-with-open-items.** The criteria are **declared** (`epics.md` Epic 7, Stories 7.1–7.4).

- Every story is `done` (`pending_stories: []`).
- **7.1** is visible in code and tests. The snapshot and outbox item are written in one local transaction with operation ID, idempotency key and base revision. Items persist until a definitive outcome. Retry is bounded (5 attempts; `sync-engine.ts:32-33`).
- **7.2** is visible in code and tests. The French states are distinct. A retryable failure keeps the draft and offers a retry. A pending submission is read-only. Transport success alone never marks the audit submitted.
- **7.3** is visible in code and tests. One transaction records the revision, the submission and the stored outcome under a per-task advisory lock. Replays return the stored body. A stale base returns 409 with current metadata. Only structural validation runs, with no invented DEP-01/02 rules. The server recalculates through the domain and enforces the identity invariant.
- **7.4** is visible in code and tests. Database triggers freeze submitted audits and refuse TRUNCATE. Both roles are refused on every mutating route, and the route inventory test (`freeze-routes.postgres.test.ts` F6) catches new ones. Tests pin one audit per task and one submission per audit.
- All gates pass on the final state.

The verdict is not plain **accepted** because of the open items:
- authorized review is available at query level only, until 9.1 (F2);
- the device and server validators are duplicated (F3);
- `App.tsx` keeps growing (F4);
- the freeze depends on database roles (F7);
- the Epic 8 concurrency and recovery edges are deferred (F9).

No blocking finding is open.
